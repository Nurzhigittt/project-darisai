## Implemented

- `/brief/[lectureId]`: manual authoring and server generation of BriefNext/Handoff; review, edit with a reason, approve, reject, and publish Handoff. Generation stays pending approval. Quotes, timestamps, real cluster windows/counts and source are rendered from P3 responses; editing preserves evidence metadata. An uncertain mutation closes stale forms, discards capability links and refreshes server state once without repeating the write. Failed reconciliation blocks further writes until successful refresh.
- `/handoff`: public seminar material with the credential read only from the URL fragment and sent in the redeem body. No professor authorization, URL query token, storage of publication capabilities or invented production data.
- `/cohort/[courseId]`: aggregate Signal/Ripple table, numeric heat shading, accessibility labels and threshold explanation. Suppressed history, absent values and recorded zero remain distinct. Percentages describe observed lecture shares, never student comprehension. The contract supplies canonical IDs, not concept titles or semester series; the UI does not fabricate these.
- `/settings/autonomy/[lectureId]`: server-authoritative locked/whitelisted mode, explicit confirmation for allowance and revocation, course-wide scope explanation, actual transition counters and timestamps. The setting alone is not a claim that automatic AI publication is implemented.
- `/transcript/[lectureId]`: professor JSON import and multipart audio chunk upload, file/interval validation, processing/error/degraded states and timestamped text. Client limits are 25 MB audio and 400 JSON segments/20 MB; the server may enforce its own limits. Import uses lecture language and adds/deduplicates segments; it does not replace changed text at the same interval. The API processes upload requests synchronously, so there is no invented percentage or polling job endpoint. Failed audio chunk indices remain reserved by the current backend.
- `/replay/[lectureId]`: confirmed local Signal moments, transcript recap/citations, MCQ and free-text Socratic turns, refusal/template states, completion and local outcome/history. Requests use only the separate Replay token header. State and signed moment capabilities stay in memory and are not put in URLs or IndexedDB. Failed/uncertain one-use turns require a new discussion instead of replaying the consumed state.
- `/gapcards/[lectureId]`: fresh signed moments obtained through Replay, server-generated questions/quote backs, provenance and timestamps, keyboard-accessible flip, local review ratings and due dates. Existing cards can be reviewed without a network connection; generation needs a valid Replay token and server.
- `/gapcards`: local lecture/deck library, entry to Replay/cards and explicit confirmation before clearing a lecture's local history. IndexedDB migration preserves existing sessions/signals. Clearing history covers signals, pending records, dialogues and cards; late requests cannot restore cleared history.
- Navigation from professor home/summary/review and ended student lecture; EN/RU/KK text; supplied logo, color tokens and Source Serif 4 / IBM Plex Sans typography.

## API and privacy boundary

Existing P3 generated OpenAPI/TypeScript contracts were integrated from the team branch, not hand-edited. The only new backend behavior introduced by P1 is allowing PUT in the existing CORS middleware for the already implemented Autonomy endpoint, with tests under `backend/tests/unit/test_cors.py` so the CI unit selection executes them. P3's X-Replay-Token header allowance is preserved. No auth origin, credential or database policy was relaxed.

The new Brief, Cohort, Autonomy and Transcript screens discard old account data and ignore late success/error responses after logout, account or lecture changes. Mutations are not automatically retried. Replay input/history is bounded to P3 limits, and the backend remains responsible for ownership, state validity, authorization, citations and permitted transitions.

Synthetic contract fixtures live in tests and a separate, prominently labelled local visual preview only. Production routes have no fixture fallback. No secrets or provider keys were added to frontend code.
